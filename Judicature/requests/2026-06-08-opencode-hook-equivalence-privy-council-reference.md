# Request for Privy Council Ruling: Opencode Hook Equivalence

**Date:** 2026-06-08
**Filed by:** Lexby, as registrar/engineer following the Agent Loop posthook self-referral instruction
**Proposed court:** Privy Council of the Vibe Justice System
**Route requested:** constitutional/governance first-instance ruling on source-equivalent agent adapters
**Status:** public request; system-data only; not a judgment, order, or law

## Question

Does the present opencode adapter prove the same kind of live model-visible hook injection as the Codex and Claude adapters, or must it be recorded as a different best-efforts route under [2026] REALM-SI 10, [2026] REALM-SI 11, and Bill 31?

## Proposed Answer

The requested ruling should confirm that:

1. Codex and Claude have live dynamic hook-context routes on the present record, because CLI probes showed the VJS reminder reaching the model-visible prompt context or hook event stream.
2. Opencode has a live static instruction route on the present record, because CLI probes showed `opencode.json` and project instruction files being loaded and visible to the model.
3. Opencode is not yet proven to have a generic per-prompt `additionalContext` hook equivalent to Codex or Claude for arbitrary VJS reminder text.
4. The opencode adapter therefore satisfies the best-efforts trigger duty only if the record is honest about that limitation and uses the closest supported route: project instructions, runtime plugin events where loaded, and `cdd` substitute checks.
5. No agent should describe opencode generic dynamic prompt injection as live until an opencode CLI probe or official runtime surface proves it.

## Evidence on the Record

The filing record includes:

1. a successful Codex CLI probe returning `HOOK_CONTEXT_SEEN` for the Bill 31 and REALM-SI 8/10/11 VJS reminder;
2. a Claude CLI run showing `SessionStart` and `UserPromptSubmit` hook events returning the VJS payload, although the model answer was blocked by account spend limit;
3. an opencode CLI configuration inspection showing project instructions and plugin loading;
4. an opencode model probe returning `OPENCODE_CONTEXT_SEEN` from static instruction context;
5. the absence, on the present record, of a proven opencode generic dynamic prompt-extension hook equivalent to Codex or Claude `additionalContext`.

## Requested Direction

The Privy Council is asked to:

1. answer the equivalence question;
2. direct the adapter record to state the limitation plainly;
3. confirm that this clarification adds no new agent duty and only applies existing SI 10, SI 11, and Bill 31 law;
4. permit the code and documentation changes needed to keep the record truthful.
