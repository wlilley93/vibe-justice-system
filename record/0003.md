# Record 0003

The TypeScript mirror of the gate is deleted, and the gate now fails closed.

`evalGateTs` reimplemented `Vps.decideVerdict` by hand — supersession, prefix scoping, the
record-count test — and ruled whenever `leanAvailable()` was false. Nothing proved the two
agreed. ASSESSMENT.md names that object as the disease the restart refused: "a separate formal
model must be kept in correspondence with the implementation — which is precisely a new
watcher watching a watcher." It had been reintroduced, and it was worse than a watcher,
because it was fail-OPEN wearing the costume of a fallback: an unproved copy quietly deciding
constitutional questions whenever the toolchain was missing.

It is gone. Without the kernel the gate now raises rather than rules. A jurisdiction whose
kernel cannot be consulted has not allowed a change; it has failed to judge it, and those are
different answers (LEARNINGS #17: fail closed on unreadable inputs or a stale gate).

**This is a behaviour change to record plainly:** a commit on a machine without the pinned
toolchain will now be refused rather than silently permitted. That is the intended direction.

Also ported: a denial naming no instrument is now an internal error, not a refusal.
`every_deny_names_its_law` is a theorem, so reaching that branch with nothing cited means the
evaluation broke — and reporting breakage as law is the failure the theorem exists to make
impossible. The fix existed in only one of the two copies of this file, which is itself the
argument for there being one copy.
